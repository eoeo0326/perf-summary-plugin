PerformanceSummary를 바탕으로 이력서 구성과 내용을 추천하고 Markdown·HTML 초안을 작성하는 `resume-builder` 스킬을 추가했습니다. 성과 보고서와 이력서가 같은 작성 원칙을 참조해, 활동 목록을 넘어 문제·기여·결과가 드러나는 문장을 추천합니다.

## 달라진 사용 경험

- **전체 성과 자료에서 이력서를 작성합니다.** 월별·연간 보고서를 함께 검토하고 같은 PR의 중복과 상태 차이를 대조한 뒤 대표 사례를 고릅니다. 공고가 없으면 범용 기본형을, 공고가 있으면 직무에 맞춘 구성을 추천합니다.
- **추천과 사실 근거를 본문과 분리합니다.** 기본 결과물은 `recommendations.md`, `evidence.md`, `resume.md`, `resume.html`입니다. 확인되지 않은 프로필·수치·출시 상태는 추정하지 않습니다.
- **Markdown만 만들 수도 있습니다.** `--no-html`, “Markdown만”, “HTML 제외” 요청이면 HTML 파일을 만들지 않고 변환기도 실행하지 않습니다.
- **작성 시점을 바로 확인할 수 있습니다.** 모든 결과물 제목 아래 같은 생성 일시와 실행 환경 시간대를 표시하고, HTML 인쇄에도 유지합니다. 자료 수록 종료일과는 구분합니다.
- **이력서에 맞는 공통 원칙을 적용합니다.** 처음 읽는 사람 기준, 한 항목에 한 성취, 내부 용어 설명, 측정 조건·기여 범위·완료 상태 보존 등 10개 원칙을 두 스킬과 MCP에 함께 제공합니다. 수치나 변경 라인 수를 성과의 필수 조건으로 삼지 않습니다.
- **개인 결과물을 보존합니다.** 기본 저장 위치는 작업 폴더의 `ResumeDrafts/YYYY-MM-DD_HHmmss/`이며 기존 결과를 덮어쓰지 않습니다. 이 저장소에서는 `ResumeDrafts/`를 Git에서 제외합니다.
- **Windows 생성물 검사를 보완했습니다.** 공통 원칙과 두 스킬 파일의 LF 줄바꿈을 유지하고, 실제 CRLF 기본 설정의 체크아웃에서도 생성물 일치를 검사합니다.

## 설치 및 업데이트

### 공통 스킬

현재 프로젝트의 Claude Code와 Codex에 두 스킬을 설치합니다.

```bash
npx skills add eoeo0326/perf-summary-plugin@v1.3.0 --skill perf-summary --skill resume-builder -a claude-code -a codex
```

모든 프로젝트에서 사용하려면 `-g`를 추가합니다. 기존 설치는 `npx skills update`로 업데이트할 수 있으며, 새 `resume-builder`가 설치되지 않았다면 위 명령으로 추가합니다. 기존 플러그인 사용자는 플러그인을 업데이트하면 되며 같은 스킬을 중복 설치할 필요는 없습니다.

Claude Code에서는 `/resume-builder`, Codex에서는 `$resume-builder`를 호출합니다.

```text
$resume-builder PerformanceSummary 전체로 범용 이력서 초안을 만들어줘.
$resume-builder PerformanceSummary 전체로 Markdown만 작성해줘. --no-html
```

### 기존 MCP·플러그인 사용자

MCP만 사용하는 경우 기존 등록의 실행 인자를 다음 고정 버전 URL로 갱신합니다.

```bash
npx -y https://registry.npmjs.org/perf-summary-mcp/-/perf-summary-mcp-1.3.0.tgz
```

MCP의 기존 도구 6개와 응답 구조는 유지합니다. `get_report_context`, 기존 리소스·프롬프트에서 보고서 지침과 공통 이력서 원칙을 함께 제공합니다. `resume-builder`는 에이전트가 수행하는 스킬이며 새 MCP 도구를 추가하지 않습니다.

## 실행 환경과 호환성

- `perf-summary` 수집과 HTML 변환에는 Node.js 22 이상이 필요합니다. PR 수집에는 GitHub CLI와 조회 계정의 로그인이 필요하며 별도 LLM API 키는 필요 없습니다.
- `resume-builder`의 로컬 자료 검토와 Markdown 작성은 HTML 변환용 Node.js 실행을 요구하지 않습니다. 원격 확인이 실패해도 로컬 자료를 검토하고 확인 한계를 기록합니다.
- HTML 변환기는 `marked`를 포함한 독립 번들입니다. Markdown을 정본으로 사용하며 외부 스크립트·폰트 없이 단일 열·A4 인쇄를 지원합니다.
- PR 집계 기준은 실행 PC 시간대의 PR 생성일이며 기존과 같습니다. 기존 추적 파일을 자동으로 삭제하거나 추적 해제하지 않습니다.

## 검증

- 타입 검사, 단위·통합 테스트 48개, 빌드와 릴리스 메타데이터 검사.
- CLI·MCP의 공통 원칙 일치와 기존 MCP 도구·리소스·프롬프트 호환성.
- 실제 npm 배포 파일 설치, 개발 의존성 없는 MCP 실행과 보고서 저장.
- 실제 skills CLI를 통한 Claude Code·Codex의 링크·복사 설치와 저장소 밖 두 스킬 독립 실행.
- Markdown·HTML 생성 일시와 본문 보존, 기존 파일 덮어쓰기 방지와 `--no-html` 미생성 처리.
- `core.autocrlf=true` 체크아웃의 공통 원칙·실행 번들 일치.
- macOS·Linux·Windows × Node.js 22·24 CI.

공개 자동 검증에는 가상 자료만 사용합니다. 보고서 해석과 이력서 문장 선정은 에이전트가 수행하며, 테스트가 실제 채용 결과나 모든 입력의 작성 품질을 보장하는 것은 아닙니다.
