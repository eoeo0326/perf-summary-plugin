# 이력서 작성 결과 형식

모든 문서는 첫 H1 제목 바로 다음에 동일한 `> 생성 일시: YYYY-MM-DD HH:mm:ss (시간대)`를 둔다. 생성 시각은 이번 작성 실행 시각이며, 자료 종료일·조회일과 다르다. 아래 슬롯은 작성 안내이며 결과에 그대로 남기지 않는다.

## recommendations.md

- 검토한 자료의 범위와 대상, 범용/공고 맞춤 여부.
- 이력서에서 보여줄 핵심 강점과 그 근거.
- 추천 섹션 순서·비중, 본문과 선택 상세의 분량, 각 배치의 이유. 페이지 수·사례 수는 고정하지 않는다.
- 선정한 사례, 제외·통합·축약한 내용과 이유. 같은 사례는 한 곳에서 상세히 설명하고 앞쪽 요약은 짧게 쓴다.
- 공고가 있으면 업무·필수·우대 요구에 직접/인접/근거 없음으로 대응한다. 공고가 없으면 해당 매핑을 만들지 않는다.
- 자료 부족·미확정 의미·사용자에게 확인할 프로필과 질문. 완료하지 않은 자료 검토·원격 확인·시각 검증의 한계.

## evidence.md

먼저 전체 파일 목록을 읽음/제외/읽기 실패/미검토로 나누고 각 이유·읽은 범위를 기록한다. 목록과 실제 검토가 일치해야 하며, 전체를 읽지 못했으면 전체 검토 완료라고 쓰지 않는다. 이어서 자료 수록 기간·보고서 생성/조회 시점·추가 PR 확인 시점을 기록한다.

| 사용 위치·문장 | 문제·본인 행동·결과 | 출처 파일·절·PR URL | 상태·조회 시점 | 측정 조건·기여 범위 | 미확정·사용자 확인 |
|---|---|---|---|---|---|

월별·연간에 중복된 같은 PR은 하나로 합치되 서로 다른 설명과 조회 시점의 충돌은 남긴다. 개별 PR 설명이 없는 종합 문장, 축약 근거, 부분 보고서는 그 한계를 표시한다. 비병합·취소·철회된 작업은 완료 성과에서 제외한다. 팀·상위 조사에서 확인한 수치를 본인 단독 검증으로 바꾸지 않는다.

## resume.md / resume.html

- 확인된 프로필과 경력·성과를 바탕으로 실제 문장을 작성한다. 프로필이 없으면 이름·근무 기간을 만들지 말고 확인된 프로젝트 중심으로 구성한다. 교육·자격 등 없는 정보는 섹션째 생략한다.
- 첫 H1은 확인된 이름과 직무, 또는 프로필이 없으면 ‘이력서’처럼 사실을 추가하지 않는 제목을 쓴다. 바로 다음 blockquote에 생성 일시를 둔다.
- H2로 경력·프로젝트 등 섹션, H3로 대표 사례를 구성할 수 있다. 한 사례는 제목과 필요한 1~2문장 또는 불릿으로 시작하되 모든 사례에 같은 길이·형식을 강제하지 않는다.
- 출처표·검토 메모·누락 질문은 evidence와 recommendations에 둔다. 기술명만 나열하지 않고 성과를 설명하는 데 필요한 기술을 남긴다. 사용자 제공 프로젝트·연락 링크는 유지할 수 있다.
- HTML은 Markdown에서 변환한다. 본문과 수치·날짜·링크가 같아야 하며 생성 일시도 화면·인쇄에 표시한다. 원시 HTML 대신 표준 Markdown을 쓰며, 변환기는 원시 HTML을 텍스트로 표시한다. 외부 이미지 대신 필요한 설명과 링크를 쓴다.
- 지면이 길어지면 사례·중복·부수 기술부터 줄인다. 글자를 자동 축소하거나 고정 높이로 내용을 자르지 않는다. HTML은 유동적인 단일 열과 A4 인쇄 스타일을 사용한다.

## 행동 검토 사례

공개 검증에는 가상 자료를 사용하며 실제 개인 보고서·이력서를 커밋하지 않는다.

| 입력 상황 | 기대 판단 |
|---|---|
| 월별·연간에 같은 PR, 오래된 보고서는 open이고 최신 조회는 merged | PR URL로 한 사례로 묶고 최신 확인 상태 사용. 병합을 출시로 확대하지 않음 |
| 연간 요약은 앱 적용 완료라고 쓰지만 해당 PR은 closed·미병합 | 개별 PR 확인 후 앱 적용 완료 제외. 확인된 라이브러리 구현만 사용 |
| 본문에 특정 영상·기기 조건의 용량 감소 수치 | 조건과 단위를 유지. 모든 영상의 일반 절감률로 주장하지 않음 |
| 숫자가 없는 통신 교착 해결 | 문제·수정·가능해진 동작으로 대표 성과 추천 가능 |
| 축약 본문에 내부 약어만 있고 원격 접근 실패 | 약어 의미를 추정하지 않음. 확인된 범위로 축소하거나 제외하고 질문 분리 |
| 학력·직책·근무 기간이 없고 PR 생성 날짜만 존재 | 경력 연차·고용 관계를 만들지 않고 확인된 프로젝트 중심 초안 완성 |
| 여러 프로젝트의 유사 모듈·API 변경 | 해결한 문제가 같으면 통합. 관계없는 장애를 하나의 불릿에 묶지 않음 |
| --no-html 또는 Markdown만 요청 | Markdown 문서만 생성. 렌더러·Node 확인·실행 없이 완료 |
